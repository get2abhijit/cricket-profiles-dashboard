The dataset is published encrypted. Only someone with the access key can read it; refreshed automatically every week.

all players, complete dataset

Every player is keyed by the Cricsheet ID, the same ID used in Cricsheet ball-by-ball files (info.registry.people), so it joins without name matching.

Load it directly in your application (always the latest version)

Copy client/cpp_client.py from the repository into your project · pip install requests cryptography · set CPP_USER and CPP_KEY in the environment (never in code).

import pandas as pd
from cpp_client import load_players

players = pd.json_normalize(list(load_players(url="data/").values()))
# e.g. bowling style of each bowler in your deliveries table
deliveries = deliveries.merge(players[["id", "bowling.code", "bowling.kind"]],
                              left_on="bowler_id", right_on="id", how="left")

Key fields

batting.code
RHB or LHB
bowling.code
Pace: R/L + F (fast), FM, MF, M, SM, e.g. RFM. Spin: OB off-break, LB leg-break, LBG leg-break googly, SLA slow left-arm orthodox, LWS left-arm wrist-spin.
bowling.also
secondary style codes when a player bowls more than one style
bowling.status
bowls, does-not-bowl, not-listed (profile lists no bowling, usually a non-bowler), unknown
role.primary
batter, bowler, allrounder, batting-/bowling-allrounder, wicketkeeper-batter
era
current (played since 2021) or historical (last played earlier). For any other cut-off use activity.latest_match.
provenance
where each field came from (manual, cricinfo, cricbuzz, wikipedia, web-search) and whether you verified it
ids
cricinfo, cricbuzz, cricketarchive, opta, nvplay, pulse, bcci, …
